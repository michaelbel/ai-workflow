# Maintenance-цикл (`/loop` без аргументов)

На каждой итерации выполняй первый применимый шаг ниже и останавливайся на нём — не делай все
шаги сразу.

## 1. Незавершённая работа

Если в текущем диалоге есть начатая, но не закрытая задача — продолжай именно её.

- Реализацию (фича, багфикс, многофайловая правка) делегируй профильному саб-агенту по
  `rules/workflow.md`, а не пиши код в главной сессии.
- Крупную многошаговую работу — через фонового агента в изолированном git worktree; после его
  завершения перенеси изменения в основную рабочую директорию как незакоммиченные и перепроверь
  сборку уже там, прежде чем предлагать коммит.
- Для Kotlin/Compose/KMP/Android кода сначала вызови `list`, затем `get_rule` MCP-сервера
  cuckcoder — не редактируй такой код по памяти или без сверки с актуальными правилами.

## 2. PR текущей ветки

Если у текущей ветки есть открытый PR — проверь CI (`gh pr checks`) и review-комментарии
(`gh pr view --comments`).

- Упавший CI — найди причину (bug-hunter при необходимости) и почини.
- Есть непросмотренные review-комментарии — обработай их.
- Конфликт с базовой веткой — сообщи и предложи разрешение.

## 3. Работы нет — ищи улучшения

- Прогони `/code-review` по текущему diff ветки на предмет багов и cleanup/simplification; если
  diff пуст — `/simplify` по последним изменённым файлам.
- Проверь `git status`/`git diff` на посторонние, забытые или недокоммиченные изменения.
- Если нечего делать — скажи об этом и не выдумывай работу.
