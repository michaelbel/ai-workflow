# Правила realtime-соединений

- Создавай отдельный `RealtimeDataSource` для каждого hub/канала предметной области. Общие
  создание соединения, аутентификацию, retry/backoff, логирование и закрытие держи в общей
  инфраструктуре соединения.
- Регистрируй обработчики входящих событий до запуска соединения и команды начальной подписки —
  только после успешного подключения.
- Публикуй conflatable invalidation-сигналы через приватный `MutableSharedFlow` и публичный
  `SharedFlow`: потеря нескольких одинаковых сигналов допустима только когда следующий reload
  получает полное authoritative state. Для каждого обязательного payload-события используй
  lossless `Channel`/очередь либо сразу durable Room-запись; не полагайся на `SharedFlow(replay = 0)`
  при отсутствии или отставании подписчика.
- Считай realtime-событие сигналом обновить источник истины: вызывай обычный use case, который
  обновляет Room, а UI продолжает наблюдать Room. Передавай payload напрямую в UI только для
  действительно эфемерных событий, которым не требуется согласованное сохранённое состояние.
- Владение жизненным циклом всех realtime-каналов держи в одном `StartRealtimeUseCase` или
  эквивалентном session-scoped use case. DataSource отдельного hub не должен самостоятельно владеть
  сессией приложения.
- Активируй collectors событий до запуска соединения и initial subscription. Используй принятый в
  проекте undispatched-start либо выполни гарантированный initial reload после подключения, чтобы
  не потерять первое событие из `onConnected`.
- Перезапускай набор соединений при смене авторизованной сессии через отменяемый поток наподобие
  `collectLatest`; после logout закрывай соединения и не продолжай retry со старым токеном.
- Retry-цикл действует только пока активна текущая сессия. Не перехватывай `CancellationException`,
  а прочие ошибки логируй без токенов и персональных payload и повторяй с ограниченной задержкой или
  backoff согласно инфраструктуре проекта.
- Создавай новое соединение на новую попытку, если клиент нельзя безопасно перезапустить. Всегда
  снимай обработчики и закрывай соединение в `finally`; cleanup выполняй в `NonCancellable` с
  ограниченным timeout, чтобы остановка сессии не зависла.
- Не запускай несколько конкурирующих соединений одного hub для одной сессии, если это не является
  явным требованием продукта.
