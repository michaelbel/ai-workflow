# Form screen

Используй этот режим для редактируемых полей, локальной валидации и отправки формы.

## Контракт

- Храни значения полей, ошибки и nullable submit-`Job` в Model; вычисляй `isSubmitting` из
  активности `Job`. Не делай `remember` источником истины для бизнес-полей.
- Создай отдельный `data class` intent для изменения каждого логически независимого поля и
  `data object` для Submit/Retry/Back. Сохрани порядок `data object` перед `data class`.
- В field-change ветке обновляй Model через `reduce`; очищай только ошибку изменённого поля, если
  это соответствует UX.
- Перед submit проверь UI-валидацию, одним `reduce` отобрази ошибки и не вызывай use case при
  невалидной форме. Domain-валидация остаётся внутри use case/domain слоя.
- Для двух и более значений передавай вложенный `{UseCase}.Params`, а не `Pair`, `Triple` или map.
- При submit сохрани запущенный `Job` в Model и сбрось его через `invokeOnCompletion`; состояние
  кнопки выводи из `isSubmitting`. Успех, требующий навигации/snackbar, отправляй через Event;
  ожидаемые ошибки обрабатывай в `catch`.
- Если форма сначала загружает данные, дополнительно используй network-only или Room-backed
  reference только для этого потока и не смешивай load intent с submit intent.
