# Network-only screen

Используй этот режим, когда результат запроса нужен только текущему экрану и сохранять его в Room
не требуется.

## Контракт

- Добавь `LoadData` или семантический одноразовый intent, поле результата и nullable `Job` запроса в
  Model. Вычисляй loading из активности этого `Job`; не храни отдельный изменяемый boolean.
- В `init` отправляй load intent, если запрос должен выполняться при создании ViewModel. Не дублируй
  запуск через `LaunchedEffect` в Screen.
- В ветке intent запусти `Job`, сохрани его в Model, сбрось через `invokeOnCompletion`, вызови use
  case через `.getOrThrow()` и сохрани успешный результат через `reduce`.
- Обработай ожидаемые domain/network исключения в `catch` согласно соседним ViewModel. Не храни
  `Result` в Model.
- Для retry используй тот же load intent; отдельный intent нужен только если пользовательское
  действие имеет отличную семантику.

Если сетевой контракт или use case отсутствует, создай их через `create-ktor-endpoint` и
`create-usecase`. Не добавляй Room только для унификации с другими экранами.
