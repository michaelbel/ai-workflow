# AndroidX Source Rules

## Когда использовать AndroidX

Используй <https://github.com/androidx/androidx> для:

- проверки фактического поведения API;
- чтения KDoc и публичных сигнатур;
- поиска официальных samples и тестов;
- понимания default values и внутренних связей;
- восстановления примера, которого нет в документации.

## Фиксация источника

Для каждого изученного AndroidX-файла добавь в `.guidekit/SOURCES.md`:

- repository URL;
- commit SHA, tag или release branch;
- полный путь к файлу;
- ссылка на файл;
- что именно было использовано;
- использование: `reference`, `adapted` или `copied`.

Не используй плавающую ссылку на `androidx-main` как единственную фиксацию версии. Сохрани конкретный commit SHA.

## Адаптация кода

Предпочитай написать минимальный пример заново на основе понимания API.

Если фрагмент адаптирован:

- укажи исходный файл;
- опиши изменения;
- сохрани применимые copyright notices;
- не выдавай код AndroidX за полностью авторский.

Если фрагмент скопирован:

- сохрани исходный copyright header в файле;
- добавь Apache License 2.0 в `LICENSES/Apache-2.0.txt`;
- добавь запись в `THIRD_PARTY_NOTICES.md`;
- проверь, есть ли в исходном subtree файл `NOTICE` и перенеси применимые notices;
- не удаляй лицензионные комментарии.

Это правило относится к коду, тестам, изображениям и другим материалам.

## Ограничение копирования

Не переноси в учебный проект большие внутренние реализации AndroidX, если гайд можно показать через публичный API. Копирование должно быть минимальным, объяснимым и совместимым с лицензией источника.
