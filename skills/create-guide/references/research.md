# Research Rules

## Цель

Исследование должно ответить:

- какую проблему решает API;
- какая у него ментальная модель;
- какие компоненты входят в публичный API;
- как компоненты взаимодействуют;
- какие версии и opt-in нужны;
- какие сценарии необходимо показать;
- какие ограничения, ошибки и edge cases важны.

## Приоритет источников

1. Официальная документация.
2. Исходный код AndroidX или AOSP.
3. Официальные samples и тесты.
4. Release notes и changelog.
5. Официальный issue tracker.
6. Сторонние материалы как дополнительный контекст.

Существующие Notion-гайды и репозитории Михаила — эталон формы, но не источник актуального поведения API.

## Проверка актуальности

Перед реализацией:

- найди актуальную версию библиотеки в официальных release notes или репозитории;
- проверь статус API;
- проверь минимальный API level;
- проверь package и artifact coordinates;
- проверь, не был ли API переименован или deprecated;
- зафиксируй дату исследования.

Не используй версию только потому, что помнишь её или увидел в сторонней статье.

## Research report

`.guidekit/research.md` должен содержать:

```markdown
# Research

Дата: YYYY-MM-DD
Тема: ...
Статус API: ...
Версия: ...

## Главная идея

## Публичные компоненты

## Сценарии

## Ограничения

## Открытые вопросы

## Первичные источники
```

Каждое спорное техническое утверждение связывай с источником. Авторскую рекомендацию явно называй рекомендацией, а не поведением платформы.
